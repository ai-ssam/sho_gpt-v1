# Shoulder ROM Lab · VS Code 실행 패키지

카메라 촬영 또는 영상 파일로 AB·FE·ER·BIR·CIR을 분석하는 로컬 웹 앱입니다.
버전 4.0 / 패키지 작성 2026-09-27.

### v4.0.2 프레임 대기 수정 (2026-09-27)

- 이미 준비된 첫 프레임은 불필요한 탐색/화면 합성 알림을 기다리지 않습니다.
- 이후 프레임은 `requestVideoFrameCallback` 확인 또는 `seeked` + `readyState >= 2` + 요청 시각 일치로 처리합니다. 단순 타이머 경과나 currentTime 변경만으로 성공 처리하지 않습니다.
- 콜백으로 실제 PTS를 확인하지 못하면 `decodeTime`은 null로 기록하고 `decodeSeekTime`, `decodeVerification`을 따로 저장합니다. 대표 이미지도 확인 방식을 기록합니다.
- 10µs 이동 대신 프레임 내부로 최대 5ms 이동하여 미세 이동이 0으로 반올림되는 문제를 줄입니다. 취소/중복 이동은 대기 이벤트를 해제합니다.
- 등록 화면의 실패 카드에서 바로 다시 분석할 수 있습니다. 새 모듈 URL과 화면 버전 표기로 구버전 캐시를 구분합니다.
- 자동검사 33개 통과: 콜백 미발생, 연속/역방향 이동, 준비 지연, 취소 등을 모사한 검사입니다. 실제 iOS Safari·Android·PC 브라우저에서 전체 분석이 완료되는지는 아직 검증되지 않았습니다.

### iOS 업로드 안정화 수정 (2026-09-27)

- MP4/MOV 전체 파일 대신 moov 시간표만 읽습니다. 큰 WebM(32 MB 초과)은 FPS 추정으로 표시됩니다.
- iOS는 분석 입력의 긴 변을 960px로 제한하고 손 검출 모델을 재사용합니다. 데스크톱 입력은 최대 1280px입니다. 검출 결과는 정규화 좌표이며, 원본 프레임 시간표는 유지합니다.
- iOS 분석 중 중복 미리보기 디코딩을 줄이고 작업 종료 시 모델 메모리를 해제합니다.
- 뒤로가기 캐시 복귀 시 영상 URL을 보존합니다. 화면이 다시 시작되면 같은 탭의 입력 정보만 복구하며, 저장하지 않은 결과와 원본 영상은 자동 복구하지 않습니다.
- 자동검사 29개 통과. iOS 실기기에서 보고된 재시작 원인은 아직 확정되지 않았으며, 이 수정은 확인된 메모리 과다 사용 경로 및 복귀 처리 결함을 보완합니다. 실제 iPhone에서 파일 선택과 분석 완료를 확인해야 합니다.

## 빠른 실행

1. Node.js 22 이상과 VS Code를 설치합니다.
2. ZIP을 압축 해제한 뒤, VS Code의 **파일 → 폴더 열기**에서 이 README와 package.json이 있는 폴더를 엽니다.
3. VS Code의 **터미널 → 새 터미널**에서 아래 명령을 차례로 실행합니다.

```sh
npm ci
npm run dev
```

4. Chrome 또는 Edge에서 **http://localhost:4173** 을 엽니다.
5. 종료할 때 터미널에서 **Ctrl+C**를 누릅니다.

Windows에서는 start-local.bat 실행도 가능합니다. 최초 의존성 설치에는 인터넷이 필요합니다.
PowerShell에서 npm.ps1 실행이 제한되는 경우 보안 정책을 바꾸지 말고 `npm.cmd ci`, `npm.cmd run dev`를 사용하거나 VS Code 터미널을 명령 프롬프트로 선택하세요.
모델·WASM 파일은 dist/vendor에 포함되어 있어 앱 분석 중 외부 모델 CDN을 사용하지 않습니다.
HTML을 더블클릭해 file://로 열면 Worker·모델·카메라가 정상 실행되지 않습니다.

## VS Code 디버깅

최초 `npm ci` 이후 F5 → **ROM Lab: Chrome에서 실행**.
또는 터미널 메뉴의 작업 실행에서 **ROM Lab: 실행**, **ROM Lab: 테스트**를 선택합니다.
이미 서버가 실행 중이면 F5로 서버를 중복 실행하지 말고 해당 브라우저 주소를 여세요.
기본 포트 4173이 사용 중이면 기존 서버를 종료한 뒤 실행합니다.

## 사용 순서

1. 환자번호·성별·나이·측정 팔을 설정합니다. 기능 점검에는 임시환자를 사용할 수 있습니다.
2. 동작 카드를 선택해 해당 영상을 등록하거나 카메라로 촬영합니다.
3. 등록 즉시 별도 Worker에서 분석합니다. 다음 동작으로 이동하거나 영상을 추가해도 이전 작업은 계속됩니다.
4. 5개 동작이 모두 등록되면 **최종 분석 · 결과 보기**가 활성화됩니다.
5. 결과 화면에서 분석 진행 상태와 동작별 결과를 확인합니다. 아직 처리 중인 항목은 완료 후 상세결과가 활성화됩니다.
6. **상세결과 · 관절점 수정**에서 좌표를 드래그하거나 숫자로 수정합니다.
7. **수정 내용 반영**으로 최종 결과에 적용하거나 **수정 취소 · 결과로**로 되돌립니다.
8. **전체 결과 저장**, **환자 전체 JSON**, **현재 동작 CSV**, **JPG 저장**을 사용합니다.

자동 분석은 브라우저 내부에서 수행합니다. 서버가 대신 분석하거나 브라우저 종료 후 계속 처리하는 방식이 아닙니다.
분석 중에는 탭을 열어 두세요. 다른 앱으로 전환·화면 잠금 시 브라우저 정책에 따라 느려지거나 일시 정지할 수 있습니다.
5개 작업은 메모리·CPU 사용을 제한하기 위해 한 번에 하나씩 처리됩니다.

## 포함 기능

- 카메라 장치·촬영 방향·해상도·FPS·카운트다운·미리보기 좌우 반전 설정
- 무음 촬영, 최대 2분 자동 종료, 원본 영상 다운로드, 장치 해제 및 오류 안내
- 미리보기 반전과 원본 분석 좌표 분리
- 업로드·카메라 영상 공통 분석 큐, 재등록 시 해당 동작만 교체, 실패 작업 재시도
- 측면 FE/ER/CIR에서 양쪽 어깨·골반·몸통을 유지하고 반대쪽 팔꿈치·손목·손끝 숨김
- Pose + Hand 엄지 끝 검출 및 손 주변 확대 재검출
- BIR 팔꿈치 최소각과 최대 척추 도달 높이를 별도 프레임·시간으로 저장
- BIR 엄지 우선/손목 대체, 추적점 지정, 척추 레벨 수동 확정
- CIR 엄지 끝만 추적, 손목 대체 없음
- CIR 짧은 미검출 시간 보간, 긴 공백 구분, 자동/수동 구간 및 원 적합 분석
- 대표 프레임 자동/수동/최종값 분리, 수동 선택 복원
- 영상 디코딩 시각 확인 후 동일 프레임 배경·스켈레톤 캡처
- MP4/MOV 샘플 시간표, 일반적인 WebM 블록 시각으로 원본 프레임 매핑
- 가로·세로 비율을 반영한 관절각 계산
- 원본 좌표·자동 결과 보존, 수정 중 임시본과 반영된 최종 결과 분리
- IndexedDB 로컬 저장, JSON 백업/복원, CSV 내보내기, 저장 기록 삭제

ER은 이번 개발 요구사항에 따라 **어깨 신전**으로 표시·계산합니다.
외회전 검사로 사용하는 경우 검사 정의와 계산 방식부터 별도로 변경해야 합니다.

## 보관과 개인정보

환자 영상·좌표는 외부 서버로 전송하지 않습니다. 영상은 자동 영구 저장하지 않으며 촬영 원본은 직접 다운로드하세요.
저장 결과에는 환자정보·좌표·대표 이미지가 포함되고 이 브라우저의 IndexedDB에 보관됩니다.
브라우저 데이터 삭제 시 기록도 사라지므로 JSON으로 백업하세요. 공용기기에서 사용 후 저장 기록을 삭제하세요.
저장 결과를 불러온 뒤 원본 영상을 다시 연결해야 실제 영상 배경을 포함한 새 대표 이미지를 만들 수 있습니다.
JSON/CSV/대표 이미지는 개인정보가 포함될 수 있으므로 취급에 주의하세요.

## 수치와 데이터 정의

- 화면 프레임 번호: 1부터 시작. JSON/CSV sourceFrame: 0부터 시작.
- auto/manual/finalRepresentativeFrame: 분석 배열 인덱스.
- 대응 원본 번호: auto/manual/finalRepresentativeSourceFrame.
- cirManualStartFrame/cirManualEndFrame: 분석 배열 인덱스.
- 대응 원본 번호: cirManualStartSourceFrame/cirManualEndSourceFrame.
- stillImageSourceFrame/stillImageTime/stillImageDecodeTime: 이미지 원본 프레임·영상 시각·확인한 디코딩 시각.
- 원본 시간표를 읽지 못한 형식은 estimated-fps로 명시하며 프레임 번호는 추정값입니다.
- 일반 ROM: 관측된 어깨각의 최대값−최소값. 대표 프레임의 현재 각도와 전체 ROM은 별개입니다.
- BIR 높이 지수: (골반 Y−손 기준점 Y)/(골반 Y−어깨 Y) ×100.
- 척추 레벨: 상대 높이 환산 시험 기준입니다. 척추 번호 직접 검출이나 임상 검증 기준이 아닙니다.
- CIR 진원도: max(0,100−반지름 변동계수[%]). 완성도와 별개인 2D 형상 지표입니다.
- CIR 흔들림: 반지름 표준편차/평균 반지름 ×100. 임상 떨림 지표가 아닙니다.
- CIR 회전범위: 끊김 없는 구간의 각도 순변화 범위. 왕복 이동량을 한 바퀴로 합산하지 않습니다.
- CIR 연결 기본값: 원본 누락 5프레임 이하 AND 양 끝 검출 간격 0.2초 이하. 상세결과에서 조절 가능.
- 손끝 검출률은 직접 검출만 계산하며 수동·보간·미검출 프레임은 따로 기록합니다.
- 검출 부족/긴 공백은 판정 보류로 표시합니다. 정상 질환 판정을 생성하지 않습니다.

## 테스트

```sh
npm test
```

기본 테스트는 분석 계산, 큐, DOM 기반 화면 흐름, 카메라 모의 장치 동작, 캡처 동기화 계약을 검사합니다.
FFmpeg가 없으면 WebM 생성 테스트 1개만 건너뜁니다. 앱 실행 자체에는 FFmpeg와 Python이 필요하지 않습니다.

샘플 영상의 실제 프레임·타임스탬프를 검사하려면 FFmpeg/ffprobe를 설치하고 테스트 영상 경로를 지정합니다.
샘플 영상은 개인정보 보호를 위해 ZIP에 포함하지 않습니다.

PowerShell:
```powershell
$env:SHOULDER_SAMPLE_VIDEO_DIR="C:\videos\shoulder"
npm test
```

macOS/Linux:
```sh
SHOULDER_SAMPLE_VIDEO_DIR=/path/to/videos npm test
```

독립 Python 모델 점검 스크립트는 tests/sample-inference.py에 있습니다.
해당 스크립트의 런타임은 웹 브라우저 런타임과 다릅니다. 결과를 브라우저 검증이나 임상 정확도로 간주하지 않습니다.

## 검증 범위와 남은 확인

- 제공된 5개 영상 671프레임의 디코딩 수와 MP4/MOV 타임스탬프 대조 완료.
- 동일 모델 파일의 독립 Python 실행에서 포즈 검출 671/671.
- 확대 재검출 후 엄지 검출: AB 147/160, FE 87/105, ER 106/106, BIR 140/140, CIR 92/160.
- CIR은 긴 미검출 구간이 남아 자동 결과가 판정 보류입니다. 상세결과에서 손끝 좌표와 구간을 확인·수정해야 합니다.
- 정답 관절각·척추 레벨의 전문가 라벨이 없어 임상 정확도는 검증하지 않았습니다.
- 테스트 환경의 브라우저 미리보기 접근 제한으로 실제 브라우저 종단간 테스트와 카메라 실기기 검증은 완료하지 못했습니다.
- 실제 사용 전 로컬 Chrome/Edge에서 5개 영상의 업로드→결과→수정→반영→저장 및 카메라 촬영을 확인하세요.
